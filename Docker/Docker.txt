	-when you install the docker it will install the docker client also, where we can run the docker commands
	-After that check whether the docker is installed or not, by using the below commands
		: docker –version
		: sudo systemctl status docker
	-when you install docker only root user can get all the permissions, but non-root user didn't have the access.
	-to check whether the group is created or not, use below commands
		: sudo cat /etc/gshadow | grep docker
	-for providing access to non-root users, we need add the non-root users to the docker group
		: sudo usermod -aG docker non-root_user
	-docker group, which is created by default when we installed the docker.
	-to check whether the user added to group or not, we use below commands
		: id user_name
	-then need to update the permissions for the non-root user, run the below commands
		: newgrp docker
	-then check the permissions are granted or not, run the below commands
		: docker images

		: /var/lib/docker

	if it's not present in that path, then deamon will request the docker registry or hub for that image, then docker registry 
	will respond to for the pull request and it will provide the requested image, then it will store in the /var/lib/docker/images
	-we can pull the image by using below command,
		: docker pull image_name

	-to check wheather the image is pulled or not, run below command
		: docker images

	-to check the all containers (running and not running), we can use below command

	Derivatives in Docker file
	
	-What is a Dockerfile?
		A Dockerfile is a simple text file with a set of instructions that tells Docker how to build an image.
	-Why do we use a Dockerfile?
		Here’s why it’s super useful:
		1. Automation & Reproducibility
		Instead of manually setting up an environment, you just write it once in a Dockerfile.
		Anyone else can use that same file to build the exact same image.
		2. Consistency
		Keeps your app running the same way across development, staging, and production.
		No more “it works on my machine” issues.
		3. Version Control
		You can version your Dockerfile with Git, so you can track changes to your build environment just like your code.
		4. Customization
		You decide which base image to use, what packages to install, how your app runs, etc.
		5. Lightweight Deployment
		Docker images are portable, so you can deploy your app anywhere Docker runs.
